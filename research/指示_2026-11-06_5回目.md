## 目的
オーナーから「大型犬カフェ、ハスキーカフェ、ダルメシアンカフェとか、探せばまだまだあるでしょ」と言われた。
これまでの調べ方は「犬カフェ」「〇〇県 犬 ふれあい」のような一般語が中心で、**犬種名・テーマ名で探す**ことをしていなかった。今回はそこを埋める。
「東京・大阪が多いから見送る」「件数のバランスで見送る」は禁止。公式で確認できた店は全部入れる。

## 必ず読む
- `運用マニュアル.md` の「全員の禁止事項」「2. データの決まり」（JSON の項目、features の語彙、price_level、reservation、掲載対象の定義、id の形式、説明文は「だ・である」調2〜3文）
- 既存の店は `data/cafes/*.json` に入っている。**同じ店を二重に入れない**。開始時に次で名前一覧を出して控える：
  `cd /Users/suzukiissei/ClaudeCode/animal-cafe-portal && python3 -c "import json,glob;[print(c['prefecture'],c['name']) for p in glob.glob('data/cafes/*.json') if '/_' not in p for c in json.load(open(p))]"`
- 自分の担当の過去メモ `research/<動物>_調査メモ.md` の「見送り」も読む。見送りの理由が「件数のバランス」「東京が多い」なら今回は採用候補。

## 探し方（重要）
1. **WebSearch** を主な道具にする。犬種名×「カフェ」「ふれあい」「触れ合える」「と遊べる」、テーマ名×「カフェ」、「〇〇専門 カフェ」、英語名（husky cafe tokyo など）も試す。都道府県名を足した組み合わせも回す。
2. 候補が出たら **WebFetch** か `curl -sL -A "Mozilla/5.0" <url>` で公式サイトを開き、料金・営業時間・住所・予約を確認する。公式サイトの JS 描画で本文が読めないときは `curl` の生 HTML から `grep` で拾う。
3. 公式サイトが無い店は、公式 Instagram / X / Facebook の投稿が **6か月以内**にあれば SNS を正本にしてよい（マニュアル参照）。ただし Instagram は未ログインで本文が読めないことが多い。読めなければ「見送り（Instagram のみで料金が確認できず）」と記録する。X（twitter.com / x.com）は `https://syndication.twitter.com/srv/timeline-profile/screen-name/<id>` で読めることがある。
4. まとめサイト（じゃらん、asoview、PRTIMES、ブログ）は**候補を見つける入口としてだけ使う**。載せる数字は必ず公式で確認する。公式に料金が画像でしか無い場合は、画像の説明文や alt、PRTIMES などのプレスリリース（運営会社名義）から読める料金なら採用してよく、source_note にそう書く。
5. 同じサイトへの連続アクセスは2秒以上あける。CAPTCHA・ログインの壁は越えない。アカウント登録・フォーム送信・予約・問い合わせはしない。オーナーのメールアドレスや個人情報を外部に送らない。

## 掲載する／しないの境目
- 載せる：料金を払って店の犬（動物）とふれあえる店・屋内施設。飲食の有無は問わない。予約制でもよい。保護犬カフェも載せる（features に「保護動物」「里親募集」）。
- 載せない：客が自分の犬を連れて行く「ドッグカフェ」「ドッグラン」（店の犬がいない）、ペットショップ、ブリーダー見学、動物園・牧場そのもの、閉店・休業中・開店前の店。
- 移転予定の店は、公式に新住所と営業開始日が出ていて今日以前なら新住所で載せる。未定なら見送り。

## 書く場所（他の担当と同じファイルを触らない）
- 店データ：`data/cafes/_new_<担当名>.json`（配列。新規ファイル。既存の `data/cafes/dog.json` 等は**書き換えない**。リーダーが統合する）
- 調査メモ：`research/_2026-11-06_5回目_<担当名>.md`。書くこと：試した検索語の一覧、採用した店（店名・公式URL・一言）、見送った店（店名・理由）、迷った点。
- 最後に `cd /Users/suzukiissei/ClaudeCode/animal-cafe-portal && python3 tools/check.py` でエラー0を確認する（_ファイルは check.py が読まないので、自分で JSON として読めるか `python3 -c "import json;json.load(open('data/cafes/_new_<担当名>.json'))"` を確認）。

## データの書き方の補足
- `animals` の先頭は主な動物。犬メインなら `["dog"]`、犬猫両方なら `["dog","cat"]`。
- `price` は税込の表記をそのまま要約（例：「60分1,650円（1ドリンク付き）」）。`price_level` は平日の1時間目安。
- `reservation` は公式に予約の案内が無ければ「不要」。公式が勧めていれば「推奨」。予約がないと入れないなら「必須」（このときだけ features に「予約制」）。
- `description` は「だ・である」調2〜3文。犬種名・頭数・店の特徴（大型犬が何頭、ハスキーが何頭など）を具体的に書く。公式の文章の丸写しは禁止。
- `source_note` に確認した公式ページのURLと、記載が無かった項目を書く。
- 公式に記載が無い `closed` や `access` は「公式ページに記載なし（来店前に確認を）」。最寄駅が分からなければエリア名だけ。
